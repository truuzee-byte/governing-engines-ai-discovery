1. Incident Summary
OBSERVED PROBLEM
A Replit account entered a usage-restricted state. The operator intentionally left it restricted and did
not manually instruct the system to resume Agent work. Replit later stated that, after a billing
condition cleared, project environments automatically restored and Agent activity could continue,
producing paid usage without a new prompt being submitted at those exact execution times.
Control failure
The disputed point is not whether the account became billable again. The disputed point is
whether restoration of billing eligibility was treated as authority to resume paid execution.

 Replit gave two execution mechanisms: queued background tasks auto-advancing and background

Evidence boundary
These statements do not, by themselves, prove that every disputed charge was unauthorized.
They do establish that the operator requested provenance that Replit Support said it could not
fully provide, while also describing automatic restoration and background execution behavior.
3. Control Failures Exposed
1. State coupling
Billing restoration, project restoration, Agent execution, queue release, and spend authorization
were described as connected outcomes rather than independent control states.
2. Missing re-authorization gate
No clear post-restoration operator confirmation was identified before previously stopped or queued
work could resume.
3. Incomplete execution provenance
Support said it could not provide a granular record showing creation/cancellation triggers and
reasons for every Agent run.
4. Billing attribution gap
The requested run-by-run mapping from execution event to exact charge and invoice line was not
produced.
5. Ambiguous execution mechanism
Support first described queued “Build in background” tasks, then described active-deployment
background execution. The account-specific causal mechanism was not cleanly resolved.
6. Weak operator visibility
The operator had to reconstruct queue state, task history, usage, and billing behavior after the fact
rather than seeing all charge-capable background mechanisms in one control surface.
Hard line
If a system can execute, spend money, and change state but cannot prove who authorized the
transition, execution is not governed.

Operator prompt

Governing rule
No paid Agent execution resumes after restriction without explicit post-restoration operator
confirmation.

Every billable Agent execution should produce a durable event record sufficient to reconstruct
authority, causation, state transition, and cost.

A user should never have to infer why the system resumed. Automatic state changes should be
visible, attributable, and reviewable before they create new paid execution.

6. Requested Remediation
 Identify the exact restriction event, restoration event, timestamp, and Replit system component that
changed the account state.
 Identify whether the Sep 8 [REDACTED: billing amount] payment, a usage-limit reset, a billing hold release, the later [REDACTED: billing amount]
payment, the billing-threshold change, or another event caused restoration.
 Reconcile whether queued background tasks, active-deployment background execution, or both
caused the disputed Workbook Engine runs.
 Provide all available run-level usage and charge records for the Sep 5-18 billing period.
 Identify any runs that executed after automatic restoration without a new contemporaneous operator
prompt.
 Issue a refund or account credit for charges Replit cannot tie to a clearly attributable execution
authorization event.
7. Why this matters beyond one invoice
This incident is not primarily about whether an AI Agent can work in the background. It is about
whether a system can prove the authority chain behind billable execution. As AI systems become
more autonomous, the control boundary between availability, execution permission, and spend
authority becomes a first-class systems requirement.
Control principle
Restoration of service is not the same thing as restoration of authority.
Execution principle
If the system cannot prove who authorized paid execution, that run should be automatically
flagged for billing review.
Final hard line
Execution without provenance is not governed execution.
