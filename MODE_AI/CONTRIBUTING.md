# Contributing

Work in a disposable checkout. Create a feature branch and open a pull request against the repository default branch; do not force-push or merge unrelated work. Keep changes within `MODE_AI/` unless a separate repository-wide change is agreed.

Run `python -m pytest -c pytest-offline.ini -q` from `MODE_AI/`. Report exact commands, platform, dependency versions, expected/actual result and a minimal synthetic reproduction. Private historical cases and external RP integration require separately authorized evidence; do not recreate favorable receipts or relax tests merely to make the distribution green.

Keep secrets and operational data out of commits and history. `.gitignore` is only a safeguard, not a privacy audit. Check staged diffs for credentials, personal paths, names, private prompts, records, generated builds and transcripts. Use synthetic examples, not a redacted production database. Never include real provider keys or supervisor tokens in an issue.

Preserve operator ownership, evidence custody, admission/provenance, freshness, signatures and fail-closed execution. A model critique is not an authority grant. A test mock is not RP validation. A provider-generated correct answer is not Learning unless the validated-consequence → admitted-learning → Understanding-update → later-consumption → changed-behavior chain is evidenced. Keep deterministic tests separate from live behavioral qualification.

Document changes to public contracts and staged-only portability behavior. Avoid broad capability claims. No license is added in this publication; ask the operator to resolve any licensing question rather than assuming terms or adding a license.
