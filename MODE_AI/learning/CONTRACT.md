## Required boundary

Runtime Observation -> Understanding -> external Reality Primacy -> Outcome Analysis
-> Learning eligibility -> classification -> confidence -> GovernanceDecision
-> Learning record -> Persistent Memory admissibility/version -> scoped runtime context.

Observation records. Understanding owns meaning. RP validates evidence. Outcome
Analysis owns causal analysis. Learning recommends improvements. Governance decides
durability. Persistent Memory preserves approved information. Context supplies it.
No Learning record grants execution, specification, policy, semantic or RP authority.

The integration adapter verifies the existing consumed signed RP result and archives
its exact scope, source Understanding, evidence checks and references. Learning
does not run RP or decide truth. The source Understanding must match the governed RP
snapshot. It consumes the completed GovernedUnderstanding/1.2 export (including
its final record, no-review state and empty errors), not a fresh interpretation of
the raw build command. A new review-required proposal is not completion. The final
Observation links to that source export without rewriting its original observation
identity. Preserved exact meaning maps to STABLE; the gate also accepts RESTORED,
but no inferred restoration is manufactured from an arbitrary label.

## Eligibility and evidence custody

All three upstream stages must be complete; continuity must be STABLE or RESTORED;
Outcome Analysis must be COMPLETE, with an evidenced PROVEN or SUPPORTED root cause,
no unresolved causal conditions, supported classification/confidence and operator
scope. Freshness is checked again at review. Operator approval cannot supply absent
prerequisites. Ordinary Builder PASS and recorded failures remain pending if the
causal/RP chain is incomplete. Historical pending candidates are audit artifacts,
not durable Learning records and never enter the memory gateway or prompt.

Outcome Analysis represents success/failure/recovery, supporting and contradicting
evidence, unresolved conditions, root-cause state, IDs and measurement hashes.
Current executable causal method is a bounded controlled intervention with baseline,
intervention and recovery under identical recorded controls. Only RP-admitted
validated measurements may supply support. It produces SUPPORTED, never automatic
PROVEN. Error messages, correlations, repeated claims, temporal order and filled
root-cause strings do not identify cause. Unsupported methods remain unresolved.

Classification is evidence-derived and independently represents CORRECTNESS,
OUTCOME, OPERATOR and SYSTEM. Scope, applicability, exclusions, recommendation and
analysis lineage accompany classification. Unknown targets produce no dimension.
Current capture source is the execution spine; full coverage of every interaction
is not established. Categorical confidence retains unique support/opposition and
history; corroborated records precede supported records within exact-scope retrieval.
Confidence does not establish truth.

## Governance, storage and use

GovernanceDecision preserves decision/subject/operator, exact scope, policy,
evidence/prerequisite references, timestamp and lineage. Explicit local operator
approval is required for new durability after prerequisites pass. Hash-bound review
rejects stale payloads. The append-only Learning journal remains the canonical store;
compatible supersession, coexistence, revocation and rollback history are preserved.
Pre-v2 records remain inspectable but are excluded from active context until
canonical revalidation.

The runtime, not Learning, publishes approved identities to
persistent_memory/learning_gateway.py. The gateway resolves the canonical record
itself, checks governance and lineage, and creates a distinct versioned export.
Raw conversations, raw Observation, unvalidated Understanding, unapproved candidates
and caller-asserted approval cannot enter this Learning memory path. This does not
establish that the older ordinary-fact memory path meets every v2.0 rule.

Use remains explicit and limited to the next conversational prompt in the current
thread. Operator/project/domain/capability must match exactly. Lifecycle, governance,
freshness and memory admissibility are checked again on use. Considered, selected,
excluded and injected IDs/reasons are journaled and linked to Runtime Observation.
No relevant approved export means no Learning section. Inclusion is observable;
decision_changed remains unknown rather than claiming causal influence.

## Revalidation

Triggers: NEW_EVIDENCE, CONTRADICTORY_EVIDENCE, ARCHITECTURE_CHANGE,
OPERATOR_PREFERENCE_CHANGE, GOVERNANCE_POLICY_CHANGE, RP_INVALIDATION,
REPEATED_EXECUTION_FAILURE and PERIODIC_REVIEW.
Outcomes: MAINTAIN, UPDATE, SUSPEND, DEPRECATE, ARCHIVE and REMOVE.

MAINTAIN/UPDATE need a new complete governed candidate and a different RP decision;
MAINTAIN must concern the same claim. All versions, evidence, confidence history and
GovernanceDecision references remain preserved. Stop outcomes do not need an invented
cause. A governed RP disconfirmation of the same scoped claim automatically suspends
prior influence. Periodic review is checked lazily before runtime command/use; the
existing RP validity limit bounds it, and expiration suspends pending new evidence.
No timer invents renewed validity. Other triggers are explicit operator commands;
architecture and policy changes now use governed ArchitectureChangeEvent records
and dependency closure, not arbitrary filesystem differences. Preference changes
and repeated execution failures also have automatic source paths. See
FINAL_GOVERNANCE_CLOSURE.md for the current contracts and limits.

Commands retain /learning list, show, approve, reject, revoke, restore, relate and use.
Revalidation: /learning revalidate {"id":"...","hash":"...","trigger":"NEW_EVIDENCE",
"outcome":"UPDATE","new_candidate_id":"..."}.
Hash is the current /learning show review_hash. Stop outcomes omit new_candidate_id.
